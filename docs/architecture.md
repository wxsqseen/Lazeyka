# Как устроена Лазейка

Одно Python-приложение (3.11), собранное PyInstaller в один exe. Окно — страница
на WebView2 через pywebview, значок в трее — pystray. Чужой код не правится:
пакет zapret берётся из релиза как есть, ядро tg-ws-proxy — как есть из тега.

## Модули

| Модуль | Что делает |
|---|---|
| `app/main.py` | Один экземпляр, запрос прав администратора, окно, закрытие в трей |
| `app/core.py` | Связывает всё: запуск при старте, уведомления и постоянные плашки, сторож обхода, сон и смена сети, снимок состояния для UI |
| `app/api.py` | Методы для страницы (`window.pywebview.api`), ошибки → `{ok:false}` |
| `app/errors.py` | `UserError` — ошибки с текстом для человека (не баги) |
| `app/security.py` | Защищённый DACL папки данных, очистка недоверенного содержимого |
| `app/webview_guard.py` | Замок навигации окна: только наш интерфейс, ссылки — во внешний браузер |
| `app/autostart.py` | Задание Планировщика на копию exe в Program Files |
| `app/settings.py` | `settings.json` с умолчаниями и атомарной записью |
| `app/zapret/strategies.py` | Разбор `general*.bat`: строка запуска winws как её увидел бы cmd |
| `app/zapret/pack.py` | Пакеты стратегий по версиям в `packs/<версия>` |
| `app/zapret/manager.py` | Запуск winws или службы Windows, фильтры, списки, фейки, конфликты |
| `app/zapret/runner.py` | Процесс winws: без окна, вывод в журнал, ожидание готовности |
| `app/zapret/tester.py` | Подбор стратегии (порт `utils/test zapret.ps1`), быстрая проверка, «Найти и включить» |
| `app/vpn.py` | VPN рядом с обходом: адаптеры и их драйверы, маршруты, серверы VPN, «что куда идёт» |
| `app/zapret/vpnfilter.py` | WinDivert-фильтр «только прямые интерфейсы, без серверов VPN» поверх фильтра winws |
| `app/helpdesk.py` | «Помощь»: проверка DNS на подмену, проверка отдельного сайта, отчёт без ключа и имён |
| `app/zapret/diagnostics.py` | Проверки из `service.bat → Run Diagnostics` с кнопками исправления |
| `app/zapret/migrate.py` | Перенос настроек из найденного оригинального zapret |
| `app/tgproxy/loader.py` | Загрузка ядра tg-ws-proxy: встроенного или скачанного |
| `app/tgproxy/manager.py` | Прокси в отдельном потоке, статистика, проверка маршрутов |
| `app/updates/` | Проверка и установка обновлений только по кнопке (ядра своего VPN — ещё и автообновлением) |
| `app/archive.py` | Безопасная распаковка zip (пакеты zapret и ядра своего VPN) с лимитом-параметром |
| `app/vpnclient/model.py` | Свой VPN: серверы, группы, подписки, план запуска ядра — контракт между частями пакета |
| `app/vpnclient/links.py`, `xrayjson.py`, `subscription.py`, `store.py` | Разбор ссылок и подписок (включая JSON Xray с группами), загрузка с лимитами, хранилище `profiles.json` |
| `app/vpnclient/config.py`, `routing.py`, `rules.py`, `routeprofile.py` | Конфиги sing-box и помощника Xray, маршрут «через обход» из стратегии zapret, списки для пресетов, профили маршрутизации |
| `app/vpnclient/engines.py`, `process.py`, `clash.py`, `sysproxy.py`, `diagnose.py`, `manager.py` | Ядра (загрузка с GitHub, установка, сверка, выбор релиза), процессы, API sing-box, системный прокси, понятные ошибки, менеджер (в том числе подкачка и автообновление ядер) |
| `app/vpnclient/killswitch.py`, `deeplink.py`, `backup.py`, `qr.py` | Kill switch на WFP, ссылки `lazeyka://`, резервная копия с паролем, QR |
| `app/vpnclient/guard.py` | Стражи «без ядра» для тестов и стенда интерфейса |
| `app/ui/` | Интерфейс; контракт с ядром — `docs/ui-contract.md` |

## Решения и почему

- **Стратегии читаются из .bat, а не переписываются руками.** Новый релиз
  Flowseal приносит новые стратегии — они появляются в Лазейке без её обновления.
  Неизвестные переменные в новом .bat помечают стратегию недоступной, а не ломают запуск.
- **Пакет каждой версии — в своей папке.** winws и драйвер держат файлы открытыми;
  установка рядом не упирается в блокировки, откат — смена активной версии.
- **Пользовательские списки хранятся отдельно** (`zapret/user`) и копируются в
  активный пакет перед запуском: обновление пакета их не затирает.
- **Скачанное ядро прокси грузится под своим именем модуля**, со своими синглтонами.
  Если оно несовместимо или не стартует — возвращается встроенное.
- **Права на папку данных.** Из неё winws запускается от администратора, поэтому
  писать туда может только администратор, а без прав папка не создаётся.
- **Ссылки и папки открываются от имени обычного пользователя.** Браузер и Telegram
  не должны наследовать права администратора, поэтому запуск идёт с токеном оболочки
  Windows (`CreateProcessWithTokenW`, как образец RunAsDesktopUser из SDK), а ссылку
  разбирает штатный обработчик протокола (`url.dll,FileProtocolHandler`). Голый
  `explorer.exe tg://…` нельзя: протокол он не понимает и открывает «Документы».
- **WinDivert чужих программ не трогаем.** Выгружается только драйвер, лежащий рядом
  с `winws.exe`: тот же драйвер используют VPN-клиенты и ускорители игр.
- **Defender сносит файлы — лечим ложное срабатывание, а не прячемся.** Драйвер WinDivert
  помечается как RiskTool/HackTool. Если пакет оказался удалён, Лазейка переустанавливает
  встроенную копию и ставит флаг; затем, если Defender включён и наши файлы ещё не в
  исключениях, предлагает кнопку. По ней `Add-MpPreference` делает доверенными только папки и
  файлы Лазейки — и то лишь те, что внутри `ProgramData\Lazeyka` и `Program Files\Lazeyka`
  (`winutil._under` отбрасывает всё вне их, чтобы случайный exe из «Загрузок» не попал в
  исключения). Антивирус не отключаем, процесс не прячем. Папки `ProgramData\Lazeyka` и
  `Program Files\Lazeyka` закрыты на запись для всех, кроме администратора и SYSTEM, поэтому
  исключить их безопасно. В **переносном режиме** родителем папки `LazeykaData` может владеть
  обычный пользователь (её можно подменить через writable-родителя), поэтому там кнопка не
  работает и уведомление не показывается — только обычная установка или ручное исключение.
  Статус (`Get-MpComputerStatus`, `Get-MpPreference`) узнаём по запросу, а не в горячем пути.
- **Страховка связи после включения обхода.** Редкий жёсткий конфликт (VPN с kill switch,
  антивирус) может оборвать интернет целиком. После запуска обхода фоновая проверка смотрит,
  открывается ли контрольный сайт (мимо VPN, если он есть); четыре неудачи подряд — плашка
  с кнопкой «Выключить обход». Сам обход не выключаем: вдруг так и задумано.
- **Окно на замке.** pywebview внедряет API в любую загруженную страницу и не проверяет
  источник вызова, поэтому `webview_guard` отменяет навигацию за пределы встроенного
  сервера 127.0.0.1, отключает перетаскивание и уводит `target=_blank` во внешний браузер
  тем же запуском без прав (не через `webbrowser.open`, который унаследовал бы права).
- **Пути — от Windows.** `GetSystemDirectoryW`, `SHGetKnownFolderPath`: переменные
  окружения пользователь может переопределить в `HKCU\Environment`.
- **Подбор переживает аварийный выход.** Перед паузой обхода пишется метка
  `zapret/test-in-progress.json`; при следующем запуске режим IPSet и служба возвращаются.
- **«Работает» — только после проверки.** Зелёная галочка и слово «открываются» берутся
  из быстрой проверки, сделанной при том же состоянии обхода (стратегия, фильтры, IPSet,
  пакет, время запуска winws). Что-то поменялось — старый результат прячется.
- **YouTube проверяется по серверу видео.** Сайт `youtube.com` может открываться, а видео
  при этом замедлено: быстрая проверка засчитывает YouTube, только если ответил
  `redirector.googlevideo.com`.
- **«Найти и включить» не делает полный подбор.** Сначала проверка; если всё открывается —
  ничего не меняется. Иначе контрольный сайт (ya.ru) отличает «нет интернета» от
  «обход не помогает», затем по очереди пробуются до шести лидеров прошлого подбора
  (или самые ходовые стратегии) и включается первая, с которой открылось всё. Прежняя
  стратегия запоминается — «Вернуть как было» одной кнопкой.
- **Сторож не дёргает человека из-за одного сбоя.** Проверка раз в 10 минут (первая — через
  3 минуты после запуска); при сбое — повтор через минуту, и только два сбоя подряд
  дают плашку (или запуск «Найти и включить» в автоматическом режиме — с плашкой «подбираю…»).
- **О поломках — плашка, а не уведомление** (решение владельца 2026-10-18). Что Лазейка нашла сама —
  сторож, падение winws и ядра VPN, выход через сервер, подписка по расписанию, списки и профиль маршрутов,
  автозапуск, сон и смена сети, — ставится `Core.set_alert(id, …)`: одна плашка на поломку, видна на главной и
  сверху своей страницы, повтор раз в 10 минут ничего не добавляет, крестик прячет её до следующего появления.
  Снимает плашку тот, кто знает, что прошло: удачная проверка, «работает» в статусе, действие человека или
  `Core._reconcile_alerts` в тикере. Уведомлением остаются ответы на нажатия и отчёты о смене выбора человека
  (сервер переключён на самый быстрый). Менеджерам (`ZapretManager.alert`, `VpnClientManager(alert=…)`) Core
  передаёт колбэк `core.alert(id, level|None, …)`; без него (тесты, стенд) обход шлёт прежнее уведомление, а свой
  VPN пишет в журнал. Значок в трее красится по видимым плашкам `warn`/`error`.
- **Сон и смена сети.** Пауза между тиками больше 30 секунд значит, что компьютер спал:
  соединения мертвы, прокси и обход перезапускаются. Сменился набор адресов сетевых
  адаптеров — перезапускается прокси и через 20 секунд перепроверяется обход.
- **Списки zapret и Telegram-прокси согласованы.** Встроенные домены Cloudflare-прокси
  (`*.co.uk`) zapret портит — они исключаются; свои домены Cloudflare и Worker, наоборот,
  идут через обход. Эти строки дописываются отдельным помеченным блоком только в рабочую
  копию списков пакета; списки, которые ведёт человек, не меняются.
- **Совместимость с VPN — по драйверу, а не по имени.** Туннель — это адаптер с типом
  `IF_TYPE_PROP_VIRTUAL` (Wintun, WireGuard), системный IPv6-туннель, подключение RAS с
  устройством «vpn» (`RasEnumConnectionsW` — телефонные книги бывают и свои) или виртуальный
  адаптер с драйвером VPN (TAP, OpenVPN DCO, Radmin, ZeroTier…). Имя адаптера VPN-программа выбирает сама (у Incy это «wwan99», под
  мобильный модем), поэтому на него не смотрим. Сетевая карта (`NCF_PHYSICAL`), PPPoE
  провайдера, Hyper-V и VirtualBox — прямые подключения.
- **Фильтр — «только прямые», а не «кроме туннелей».** winws сам строит фильтр (`--wf-save`
  сохраняет его до мьютекса и до открытия драйвера — так в исходниках zapret v72.9), мы
  дописываем `and (ifIdx=… or …)` и исключение серверов VPN. Новый туннель после
  переподключения VPN получает новый индекс — и не попадает в перехват, даже пока
  Лазейка не успела пересобрать фильтр. Новый прямой интерфейс замечает слежение за сетью
  (раз в 5 секунд, полный осмотр — раз в 30) и перезапускает обход.
- **Язык фильтров WinDivert** не знает `!(…)`: отрицание ставится только перед полем.
  Исключение сервера записано как `(!ip or (ip.DstAddr != S and ip.SrcAddr != S))`, чтобы
  сравнение адресов IPv4 не отрезало пакеты IPv6. Готовый фильтр проверяет
  `WinDivertHelperCompileFilter`, а тесты гоняют через `WinDivertHelperEvalFilter`
  собранные вручную пакеты: Discord через Ethernet перехватывается, внутри туннеля — нет.
- **Сервер VPN** — маршрут /32 или /128 к публичному адресу через шлюз прямого интерфейса
  (так VPN-программы выводят собственное соединение из туннеля) и адреса из
  `wg show all endpoints` у официального WireGuard, который маршрутов не прокладывает. Таких
  маршрутов больше трёх — это раздельное туннелирование, а не серверы: тогда не исключаем
  ничего, иначе вместе с «серверами» выпал бы и Discord. Адрес не исключается и тогда, когда
  по нему же сейчас отвечают Discord или YouTube (VPN через CDN).
- **Что куда идёт — по ответу сайтов.** Таблица маршрутов ничего не скажет о VPN с
  правилами внутри программы (sing-box, xray, mihomo). Поэтому сравниваем адрес, с которого
  нас видят Cloudflare (`gateway.discord.gg/cdn-cgi/trace`) и видеосерверы YouTube
  (`report_mapping`), только с подтверждёнными эталонами: запрос, привязанный к прямому
  подключению, и запрос, привязанный к самому туннелю (или через системный прокси VPN).
  Незнакомый адрес — «не удалось определить», а не догадка. IPv6 сравнивается с сетями /64
  прямых адаптеров: так виден VPN, который заворачивает только IPv4. Не открылось — значит,
  идёт мимо VPN и его режет провайдер. Все проверочные curl запускаются с `-q --noproxy *`,
  а запрос от имени Telegram-прокси — без системного прокси: иначе прокси незаметно подменил
  бы маршрут.
- **VPN в режиме системного прокси** (без туннеля, частый режим у Happ, Hiddify, v2rayN) —
  тоже VPN: локальный прокси в настройках Windows. Перехват исключать нечего, но человеку
  важно знать, что браузер и Discord идут через прокси, — окно при включении показывается.
- **Проверки обхода при VPN — мимо туннеля.** Иначе всё «открывается» через VPN, и подбор
  ничего не различает. curl получает `--interface <IPv4 прямого подключения>`, ping —
  `IcmpSendEcho2Ex` с адресом источника; при DNS-заглушках fake-ip (198.18.0.0/15) адрес
  берётся через DNS по HTTPS. Если VPN не пускает соединения мимо себя (защита от утечек),
  «Найти и включить» так и говорит, а не «нет интернета».
- **Имя VPN не угадываем.** По процессам не видно, чей туннель поднят: у владельца
  одновременно работают Incy и служба Happ. Если адаптер сам называет программу (WireGuard,
  Radmin, WARP…) — пишем её, иначе честно перечисляем кандидатов: «Incy или Happ».
- **Фильтры проб подбора лежат отдельно** от рабочего: подбор строит по фильтру на
  стратегию, и уборка старых не должна задеть файл, на который ссылается служба Windows.
- **Служба и индексы интерфейсов.** Индексы (ifIdx) Windows не обещает сохранять, а служба
  стартует с фильтром, собранным Лазейкой. Поэтому состояние фильтра службы сохраняется
  (`vpn-service.json`), и при каждом запуске Лазейка сверяет его с текущими подключениями и
  при расхождении перенастраивает службу. Пока Лазейка не запущена, расхождение не
  исправить — поэтому при работе как служба с совместимостью окно советует автозапуск.
  Полное решение — собственный служебный процесс, пересобирающий фильтр перед winws.
- **Откат не отменяется.** Встроенный пакет перебивает выбор пользователя, только если он
  новее и поставлен впервые (то есть пришёл с новой версией приложения).

### Свой VPN (подробно — `docs/vpnclient-plan.md`)

- **Два ядра, оба стабильные.** sing-box 1.14.3 — основное (TUN, системный прокси, маршруты, DNS,
  clash API со статистикой, задержкой и переключением без перезапуска). Xray 26.3.27 — помощник только
  для серверов, которых sing-box не умеет (XHTTP, mKCP, VLESS ML-KEM, gRPC multi): в конфиге sing-box такой
  сервер — выход `socks` на свой порт помощника. TUN с маршрутами у Xray на Windows пока только в
  пре-релизах, поэтому основным ядром он не стал.
- **Ядра — отдельные процессы, официальные релизы без изменений, скачиваются с GitHub.** В exe их нет
  (решение владельца 2026-10-18: exe меньше на 51 МБ, ядра обновляются без новой Лазейки, мы не
  распространяем чужие бинарники). Сразу при запуске, фоном и только с правами администратора, менеджер
  ставит недостающие ядра закреплённой версии (SHA-256 из кода) в `components/<ядро>/<версия>`; exe ядра
  сверяется перед каждым запуском. Маршрут — напрямую с закреплёнными адресами GitHub, запасной — через
  системный прокси (у человека может работать другой VPN в режиме прокси). Не скачалось — постоянная плашка
  «Скачать ещё раз» без уведомлений и повторы через 1, 5, 15 минут, дальше раз в час; «Включить» подкачку ждёт.
  Лазейка остаётся MIT: ядро получает файл конфигурации и общается по HTTP на 127.0.0.1 — это aggregate (GPL)
  и Larger Work (MPL); текст GPL-3.0 кладётся рядом с sing-box.
- **Автообновление ядер — только через `check`.** Раз в 6 часов (и после проверки «Обновлений») — самый новый
  стабильный релиз любой серии, хеш — digest GitHub. Новая версия ставится рядом и становится активной, только
  если ядро приняло конфиг текущих серверов и настроек (нет серверов — образцовый); не приняло — версия
  запоминается неподходящей и больше не скачивается. Работающий VPN не перезапускается: новая версия — со
  следующего подключения. Первый запуск новой версии — «на пробе»: упала при старте — откат на прежнюю (её
  хранит уборка), пометка и повтор; упала и прежняя — виновата не версия.
- **«Всё через сервер, кроме того, что обрабатывает обход».** Маршрут «через обход» строится по профилям
  winws активной стратегии (сеть, порты, домены, IPSet «по списку», голос Discord по процессу и портам) —
  домен вне hostlist winws не обработал бы, поэтому geosite не подмешивается. Выход правила — селектор
  `bypass` [direct, proxy]: обход работает — direct, упал — proxy, без перезапуска ядра. Домены — в
  локальных rule-set файлах: sing-box перечитывает их сам при смене списков zapret.
- **Свой VPN — не чужой.** `vpn.scan(own=…)` знает свой адаптер, PID ядер (`ppid`) и адреса серверов:
  окно «Работает VPN» про свой не спрашивает, свои серверы исключаются из перехвата winws всегда, свой
  TUN — даже при выключенной совместимости (иначе winws портил бы пакеты внутри туннеля).
- **Секреты закрыты от других программ.** Ссылки, ключи и адреса подписок — в `vpnclient/` с DACL без чтения
  для пользователей; в состояние для страницы, журнал (фильтр на обработчиках) и отчёт помощи не попадают.
- **Проверка без ядра.** На ПК разработчика работает чужой VPN: `LAZEYKA_NO_CORE=1` в тестах и стенде не даёт
  запустить ядро, тронуть системный прокси, WFP и реестр; разрешён только статический `sing-box check`.

## Проверка окна

`LAZEYKA_UI_SELFCHECK=отчёт.json Lazeyka.exe --no-elevate --hidden` (только без прав
администратора) открывает скрытое окно, проверяет мост API и отрисовку, пробует перейти
на blob-страницу и записывает, что замок навигации её отменил.
`tools/ui_bridge.py` отдаёт интерфейс с настоящим ядром по HTTP — для скриншотов
в headless Edge без окна pywebview.

## Проверки

`pytest` — разбор всех стратегий пакета, IPSet, списки, пакеты (в том числе
zip-slip и подмена хеша), настройки, перенос, hosts, ядро прокси, «Найти и включить»
на поддельном обходе (нашла / не нужно / не нашла и вернула прежнюю / откат),
согласование списков с Telegram-прокси, отчёт без ключа и имени пользователя. Сетевые тесты
(отключаются `LAZEYKA_NO_NETWORK=1`): MTProto-запрос `req_pq_multi` через прокси
до настоящего Telegram и сверка встроенного ядра с тегом на GitHub по git-хешам.

`Lazeyka.exe --selftest отчёт.json` проверяет собранный exe без изменений в системе.
